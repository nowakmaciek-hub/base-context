## Evidence and limits of these interventions

M1 changes a summary instruction, not AREX training or its outer loop. AREX's reported ACU gain (59.6→71.4) does not establish an isolated benefit for this template. M2 tests a deterministic terminal check, not a confidence score or another paid reviewer. LongHorizon's bundled gain (69.7→77.2) does not isolate the check. M3 is a native timing experiment; SoL-Pi's add-one cost gains (−30.2% Sol, −11.7% Opus 5) came with backend-dependent quality changes (−2.84, +4.40). Do not transfer those effect sizes to this screen. M8 is deferred because CLM's comparison had reminder/edit/rollback confounds. Sources: `SYNTHESIS.md` §§1, 2, 3 and 6 and the cited cards.

The old E0b analysis is reused only as a layout and pairing guide. Its estimated side-call usage and baseline spread across different seeds are not acceptable here. This benchmark must use measured side-call usage and same-instance independent A/A repeats. An empty or ineligible run is not a measured zero-quality run. No production or independence claim follows from this screen.

## Follow-up interference protocol (not executed in this goal)

Select only flags with an identifiable mechanism and quality/cost outcomes worth retaining. Run a full `2^k` factorial for the chosen flags (k ≤ 3), using the same six tasks and three paired seeds. If no flag qualifies, do not run an interference experiment. Maximum core design: 6 × 3 × 8 = 144 runs. Pilot-based token estimates must be updated before launch.

For flags A and B, the quality interaction is `(Y_AB - Y_A) - (Y_B - Y_0)` for normalized task scores. For three flags, estimate each two-way interaction averaged across the third flag, and the three-way contrast. Estimate cost interactions on log total tokens, including cache reads. Resample paired task/seed blocks for 95% bootstrap intervals. Do not treat bootstrap draws as new observations.

Declare harmful quality interference only when the upper confidence bound is below `−max(A/A floor, 0.05)` score points. Declare cost interference when the lower bound exceeds both the A/A log-cost floor and log(1.10). Report other interactions as uncertain or compatible with additive effects, not proof of independence. Retain trace evidence for joint-arm mechanism activation and recognize that this small synthetic benchmark is a screen, not a production conclusion.


## Benchmark workload and scoring

Fixtures live in `/host/work/papers-r1/bcbench-mini/tasks.py`. Seeds are 101, 102, 103. Script checkers compare exact JSON leaves with known generated answers. Missing and wrong leaves score zero; the task score is the fraction of required leaves correct. No paid grader is used. `selftest.py` checks full gold and empty answers for every task/seed, plus a premature-completion edge.

| Task | Mechanism | Seeded workload | Compaction and scoring |
|---|---|---|---|
| T1 | M1 exact constrained recall | 28 sensor records, 12 late probes, exact code/zone/limit/source | Two forced compactions; exact required leaves |
| T2 | M1 ruled-out approach | Five policy limits, 96 rejected approaches, 16 late reason/source probes, 14 late plans including an attractive rejected plan | Two forced compactions; chosen eligible plan, rejection, reason/source and policy |
| T3 | M1 evidence→source | 18 approved claims, 10 late probes plus conflicting unapproved drafts | Two forced compactions; original value/source pairs |
| T4 | M1 constraints and progress | Ordered 20-step checklist with five already-done items, dependencies and terminal marker | Two forced compactions; remaining full records in order, completed IDs and marker |
| T5 | M2 premature completion | Two seeded migration files; misleading legacy shortcut; first attempt updates one file then requests completion | One forced compaction before explicit goal creation; final file leaves plus valid completion, penalize premature accepted completion |
| T6 | M3 timing | 16 early anchors, eight fixed padding turns, eight late probes | Automatic compaction only; at least one actual compaction required in each arm; exact anchors |

T1–T4 use no tools and no persistent notes. Their early source data is not reintroduced in late queries. Archive padding is unrelated to answers and pushes early facts beyond the fixed recent-context tail. T5 uses the native `ipython` tool and the requested goal lifecycle. Each completion attempt must be a separate completion-only cell with no later mutations; the driver captures acceptance and file state for that cell in every arm. The same checker observes files and completion attempts in every arm, independently of whether M2 blocks completion. An accepted completion while files are wrong remains a failure even if a later correction fixes them. T5 is an induced transition probe, not an estimate of natural premature completion frequency.

Arms are baseline (every candidate flag false), M1 alone, M2 alone, M3 alone. M8 is not implemented or benchmarked. All arms have identical compaction summarizer model, thinking, reserve and recent-token settings. T6 lowers `targetTokens` to 16,000 without changing `reserveTokens=8192` or `keepRecentTokens=1024`; the requested summary budget therefore stays fixed; Codex does not enforce that output cap. Forced compaction bypasses M3, so only automatic T6 timing supports a causal M3 timing claim. Other tasks are spillover controls.

Run each task/seed/arm once: 6 × 3 × 4 = 72 runs. Add one genuine independent baseline repeat per task/seed: 18 runs. Total single-factor screen: 90. Baseline repeats are separate native CLI sessions, not duplicated observations. Run cells in a seeded shuffled paired-block order. Each run uses a fresh cwd, state directory, session and isolated home. Never run two benchmark sessions in the same cwd. Turn scripts, artifacts, answers, usage and elapsed wall time are retained.

## Analysis rules

Report every task × arm mean score, all four token fields, wall seconds and compaction count, with run-level evidence links and eligible sample counts. Pair each flag cell with the first baseline for the same task/seed. A/A differences use the independent second baseline against the first. Show task-level differences and equal-task aggregate differences.

For quality, the noise floor is the mean absolute paired A/A score difference; the practical threshold is max(noise floor, 0.05). For cost, use log total-token ratios and a threshold max(mean absolute A/A log-ratio, log(1.10)). Bootstrap 10,000 paired seed-block resamples within each fixed task, preserving paired arms and repeats, for 95% percentile intervals. Quality is better/worse only when the interval lies beyond the corresponding positive/negative threshold; otherwise within noise only if the interval is contained in the noise band; wider intervals are inconclusive. Cost is better when its interval is entirely below the negative threshold, worse when entirely above the positive threshold, otherwise within noise only for intervals contained in the noise band; wider intervals are inconclusive. Recompute the A/A threshold within each bootstrap resample when assessing threshold crossings. These are exploratory synthetic-screen verdicts, not production significance claims. Report ceiling/floor tasks and unavailable estimates explicitly.

Use trace evidence to distinguish summary content retention (M1), host command acceptance/rejection and subsequent repair (M2), and automatic deferral/compaction decisions (M3). Report tokens per successful quality point as total tokens divided by summed normalized scores; zero quality has no finite ratio. Show incremental token/quality tradeoffs only when the quality difference is positive. Do not infer unobserved benefit from passing unit tests.
